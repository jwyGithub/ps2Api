## 一、项目整体是什么

`ps2api`（Postman2API）是一个用 **Go 1.26** 编写的**API 网关**，核心作用：

- 把 **Postman Agent Chat**（Postman 桌面端 / Web 端的 AI 能力）伪装成标准的 **OpenAI / Anthropic 兼容 API**，对外提供 `/v1/chat/completions`、`/v1/messages`、`/v1/responses`、`/v1/models`。
- 通过**账号池（号池）**管理多个 Postman 账号的登录凭据，做**轮询 + 最少在途路由 + 失败自动切换**，突破单账号额度限制。
- 用 **SQLite** 单文件持久化账号、请求日志、统计、设置、告警。
- 自带一个**独立管理面板（Dashboard）**，当前是嵌入二进制的静态 HTML/JS（本次要迁移的对象）。

数据流：客户端 → 网关 `/v1/*` → 鉴权 → 路由选账号 → 转换协议 → 请求 Postman 上游 → SSE 流式回传 → 记录日志/统计/额度。

## 二、后端功能细分（能力清单）

### A. 协议转换 / 推理代理（`internal/api`, `internal/provider`）
- **A1** OpenAI 兼容 `POST /v1/chat/completions`（流式 + 非流式）
- **A2** OpenAI Responses API `POST /v1/responses`
- **A3** Anthropic 兼容 `POST /v1/messages`
- **A4** 模型列表 `GET /v1/models`
- **A5** SSE 流式转发与解析（`sse.go`）
- **A6** 工具调用支持：tools / tool_choice / tool_use 转换、工具模拟（`toolsim.go`）、工具护栏（`toolguard`）
- **A7** 请求/响应链路追踪 trace_id（`trace.go`，响应头 `X-PS2API-Trace-ID`）
- **A8** 上游 403 拦截识别与账号级 failover（`docs/403-gateway-block-failover.md`）
- **A9** 缓存键探针（cache-probe）度量上游缓存命中

### B. 账号池（`internal/pool`, `internal/router`, `internal/store`）
- **B1** 账号 CRUD：新增、删除、启停
- **B2** 账号导入 / 导出（`account.json` 格式，支持多文件顺序导入）
- **B3** 双认证模式：桌面版 `access_token` / Web 版 `postman.sid`
- **B4** 路由策略：轮询 + 最少在途（least-inflight）
- **B5** 失败自动切换（failover）+ 重试次数配置
- **B6** 账号状态机：active / exhausted / error / pending
- **B7** 账号来源标记：manual / local / detect-web / browser

### C. 额度 / 限流采集（`internal/provider/postman.go`, `probe.go`）
- **C1** 主动刷新官方额度快照 `POST /api/refresh-quota`
- **C2** 额度字段：limit / used / remaining / overage / spillage / state
- **C3** 额度周期：cycleStart / cycleEnd（重置倒计时）
- **C4** 官方告警阈值、超额策略（allowOverage）、额度归属（teamPooled）
- **C5** 频率限制：rateLimit / rateRemaining / rateWindowSeconds / rateResetAt
- **C6** 月度额度预测（`quota_forecast`：日均消耗、预测月用量、缺口、建议加购账号数）

### D. 统计 / 分析（`internal/store/analytics.go`, `internal/api/metrics.go`）
- **D1** 汇总统计：累计/今日请求、成功/失败数、成功率、平均延迟、P95、总 Token、成本
- **D2** 时序趋势：日/时序列（total / success / error）
- **D3** 模型分布（model / count / tokens）
- **D4** 渠道对比（channel：OpenAI vs Anthropic，含成功率/延迟/成本）
- **D5** 账号排行榜（calls / success / error / tokens / 延迟 / 评分 score）
- **D6** 活跃热力图（weekday × hour × count）
- **D7** 请求日志流 `GET /api/logs`（最近 100 条）

### E. 系统 / 运维（`internal/api`）
- **E1** 设置读写 `GET/PUT /api/settings`（写 SQLite，即时生效；含字段定义 defs）
- **E2** API Key 鉴权（Bearer，留空则关闭鉴权）
- **E3** 代理出口连通性检测 `POST /api/proxy-check`（多代理逐个探测延迟）
- **E4** 告警中心：`GET /api/alerts`、单条 resolve、全部 resolve
- **E5** 健康检查 `GET /health`
- **E6** 缓存探针开关/重置 `GET/DELETE /api/cache-probe`

## 四、新前端脚手架现状（`page/`）

- 框架：**TanStack Start**（React 19 + TanStack Router 文件路由 + TanStack Query）
- 已含：**tRPC**、**better-auth**（登录鉴权）、**Tailwind v4**、**shadcn/ui**（new-york 风格、zinc、lucide 图标）、**TanStack Table / Store**、Zod、SuperJSON
- 现有路由：仅 `index.tsx`（脚手架欢迎页）、`__root.tsx`、`api/auth/$`、`api/trpc/$`
- 结论：**目前是空脚手架**，页面功能需从零搭建；已具备表格、图表以外的全套数据/路由/鉴权基础设施。图表库需自行引入（现静态页用 Chart.js）。

### 迁移需注意的关键差异
1. **鉴权模式变化**：旧面板用 API Key + localStorage；新脚手架自带 better-auth，需决定二者关系（是否保留 API Key 管理页）。
2. **数据获取**：旧版手写 `fetch` + 5s 轮询 → 建议用 TanStack Query（`refetchInterval`）。
3. **图表**：Chart.js（雷达/折线/分布）需替换或沿用；热力图为手写 grid。
4. **后端联调**：新前端 dev 在 `:3000`，Go 网关在 `:1930`，需配置代理/CORS。
5. **动态设置表单**：settings 由后端 `defs`（key/label/type/default/description）驱动，需做通用表单渲染器。
